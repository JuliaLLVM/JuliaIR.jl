API reference

The API is not exported; use qualified names (JuliaIR.register!).

Passes

JuliaIR.register!(pb::PassBuilder; julia=VERSION, fp16=:auto, bf16=:auto,

Register every pass of this package with the pass builder pb, so that they can be used by name in its pipeline. The keyword arguments are the defaults of the options for occurrences of the passes that do not specify them (see JuliaIR.Dialect).

source
JuliaIR.PropagateAddrspacesPass — Function
JuliaIR.PropagateAddrspacesPass(; julia=VERSION)

Make loads, stores, atomics and memory intrinsics that access memory through one of Julia's special address spaces use the untracked pointer the address was derived from, when that pointer can be recovered through address space casts, GEPs, phis and selects (jl-propagate-addrspaces in a pipeline). Run dce or another cleanup afterwards to remove the instructions that became unused.

source
JuliaIR.DemoteFloat16Pass — Function
JuliaIR.DemoteFloat16Pass(; julia=VERSION, fp16=:auto, bf16=:auto)

Perform floating-point arithmetic on half (fp16) and bfloat (bf16) values in float, truncating every result, so that the IEEE semantics of the 16-bit types are preserved on targets that don't support them natively (jl-demote-float16 in a pipeline). Whether a type is demoted is decided by the policies: :demote and :keep apply to every function, :auto follows the rule of the Julia version, which reads the function's target-features (Julia 1.10, 1.11) or julia.hasfp16/julia.hasbf16 attributes (1.12 and later; without them, half is demoted only on PowerPC and bfloat is kept). Operations with all fast-math flags are left alone.

Meant to run late in the pipeline, not followed by instcombine (which would fold the conversions away); gvn can clean up redundant conversions. Unlike Julia's C++ pass, it is not skipped on optnone functions, since it affects their semantics.

source
JuliaIR.GCInvariantVerifierPass — Function
JuliaIR.GCInvariantVerifierPass(; julia=VERSION, strong=false)

Check that functions obey the invariants of Julia's GC address spaces (jl-gc-invariant-verifier in a pipeline, jl-gc-invariant-verifier<strong> for strong=true), and throw a JuliaIR.GCInvariantError listing every violation otherwise. strong also rejects GEPs of tracked pointers, which Julia's code generator never emits but the optimizer may introduce.

source

JuliaIR.GCInvariantError

The error thrown by GCInvariantVerifier (jl-gc-invariant-verifier) when a function violates GC invariants. violations lists every violation found in the function, in the order of its instructions, as JuliaIR.GCInvariantViolations.

source

JuliaIR.GCInvariantViolation

One violation of a GC invariant found by GCInvariantVerifier: the message that says which invariant, and the offending instruction, as text.

Dialects and options

JuliaIR.Dialect — Type
JuliaIR.Dialect(julia::VersionNumber; fp16=:auto, bf16=:auto, gc_barrier=:stock)
JuliaIR.Dialect(julia::AbstractString; ...)

The IR dialect emitted by Julia version julia, which every pass of this package takes as its julia option. Every Julia version from 1.10 up to the development version this package knows about is supported; a prerelease like v"1.13.0-DEV.123" has the dialect of the release it precedes, and the development version has the dialect of the Julia master commit this package is tested against. Newer versions get the development version's dialect: a new minor version starts out emitting the same IR as its predecessor, and only diverges as changes land on master.

The dialect only describes Julia's IR. What depends on the version of LLVM (e.g., the signature of the lifetime intrinsics) is determined by the library the passes run on, see JuliaIR.library_facts.

The keyword arguments are policies, which are not determined by the Julia version:

  • fp16: whether DemoteFloat16 demotes half arithmetic to float. :auto follows the rule of the Julia version (fp16_rule), :keep and :demote override it, including the function attributes that rule reads.
  • bf16: the same for bfloat arithmetic.
  • gc_barrier: the GC write-barrier configuration Julia was built with (:stock, :snapshot, :field_precise or :snapshot_field_precise).

JuliaIR.PassOptions

The options of one occurrence of a pass in a pipeline: the JuliaIR.Dialect of the IR (dialect) and the pass-specific options (extra, a NamedTuple).

source
JuliaIR.parse_options — Function
JuliaIR.parse_options(str; julia=VERSION, fp16=:auto, bf16=:auto, gc_barrier=:stock,
                      extra=(;))

Parse the option text of a pass in a pipeline (the part between < and >, e.g. julia=1.12;fp16=demote) into JuliaIR.PassOptions. Options are separated by ;. The keyword arguments are the defaults for options that are not given. extra holds the defaults of the pass-specific options, which determine how they are parsed: a Bool option is written name or no-name, a Symbol option name=value. Unknown and repeated options are rejected.

Libraries

JuliaIR.require_opaque — Function
JuliaIR.require_opaque(ctx::LLVM.Context)

Throw an error if ctx uses typed pointers. The passes only support opaque pointers; IR with typed pointers (as emitted by Julia 1.10) needs to be parsed into a context that uses opaque pointers, e.g. Context(; opaque_pointers=true), which upgrades it.

source
JuliaIR.library_facts — Function
JuliaIR.library_facts(ctx::LLVM.Context)

What the passes need to know about the LLVM library that ctx belongs to, as opposed to the Julia dialect of the IR:

  • llvm: the version of LLVM;
  • lifetime_size: whether the lifetime intrinsics take a size argument (before LLVM 22).

The jlopt driver

JuliaIR.jlopt — Function
JuliaIR.jlopt(args::Vector{String}; stdin=stdin, stdout=stdout)

Run the jlopt driver in this process: parse the module from the input named in args (or read from stdin), run the pipeline, and write the result to stdout or the file named by -o. Throws a JuliaIR.JloptError for usage errors, and the exception of a failing pass otherwise. See bin/jlopt --help for the options.
